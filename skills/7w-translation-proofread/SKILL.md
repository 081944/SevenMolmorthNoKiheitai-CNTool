# 7W 中文校对与重译

用于处理本项目 `work/translation` 下已经翻译但不够通顺、或因逐行翻译而缺少上下文的文本。目标是得到自然、连贯、术语统一且可以被 7W 工具链安全回写的中文候选稿。

## 必须先读取的资料

开始编辑前，按当前文件类型读取：

1. `work/translation/专有名词表.tsv`。这是项目术语的权威基准；命中日文词时优先使用“译名建议”列，空缺或存在冲突时记录待确认项。需要说明时再读同名 `.md`，不要把术语表复制到 skill 或另建一份。
2. `docs/工具与产物目录规范.md`，确认候选目录、工具入口、原始文件来源和验证命令。
3. 对应格式文档：SPL 读 `docs/SPL格式与重建说明.md`，NHT 读 `docs/NHT格式与重建说明.md`，FHM 读 `docs/FHM格式与重建说明.md`；涉及 ELF、影片字幕或图片中的文字时，再读 `docs/ELF内嵌文本提取与调试说明.md`、`docs/MOVIMAGE影片字幕格式与解析说明.md` 或相关 ITE/FHN 文档。
4. 当前候选文件的前后文，以及同一剧情段落、界面流程或字幕块中的相邻记录。若一句话跨多条记录，先合并理解，再分别填回原记录边界。
5. 同一角色、地点、职业、道具或系统词在当前文件及相关文件中的已有译法；发现与 TSV 不一致时以术语表为准，并统一本次涉及的文本。

术语匹配按完整词组优先于片段。带后缀的地名、人名和完整短语按表中完整译名处理，不要把术语表的备注或括号说明写进游戏文本。

## 按类型处理

先判断候选属于 `spl`、`nht`、`fhm`、`fhn`、`ui`、`elf` 还是 `movie_subtitles`。只编辑 UTF-8 候选文件；原始 `.spl`、`.nht`、`.fhm`、`.fhn`、ELF 和 `MOVIMAGE.BIN` 保持只读。

### SPL、FHM、ELF 双栏候选

常见记录如下：

```text
[0003] @0x004F9 len=22 | 日文原文|现有中文
```

- 只编辑最后一个 `|` 后的译文字段；索引、偏移、`len`、日文原文和记录顺序必须原样保留。
- 不要在译文中新增 `|`。解析器把最后一个 `|` 后的内容作为译文。
- `len` 是原始字节长度或槽位信息，不手工修改。SPL/FHM 由 `text_7w.py` 重建；ELF 是定长 NUL 结尾槽，超长必须重写措辞。
- FHM 的 `[text:n]` 必须保留真实记录号；`[tail:n]` 是独立尾部字符串，不能改成连续编号或删除空记录的语义位置。
- ELF 候选中的 `\n`、`\r` 是转义文本，不要变成真实换行；低置信度执行段候选不能直接回写，除非已经人工或运行时确认。

### NHT 帮助文本

正文由可编辑的 `[text:n]` 和只读的 `[link]`、`[keep]` 节点组成：

```text
### 条目 0001 标题=基本操作 body=0xF20 len=432
[keep] n=3
[text:0] len=36 | 日文原文|中文译文
[link] 王の間
```

- 只翻译 `[text:n]` 行最后一个 `|` 后的字段。
- 条目号、标题、`body`、`len`、节点编号、`[link]` 标题和 `[keep]` 数量都不可修改。
- `[link]` 是游戏内部热字链接，不是普通显示文本；不要翻译、删除或重排它。
- 相邻文本节点、链接和 keep 节点一起阅读，尤其注意一句话是否跨节点；译文仍按原节点边界填写，不能合并条目。

### FHN 固定字段与 UI 文本

FHN 候选一般为：

```text
[text:0] @0x1C78 len=8 | 攻撃力{T}|攻击力{T}
```

UI 候选一般为：

```text
[text:0] off=0x638 len=14 | 画面位置の調整|画面位置调整
```

- 只编辑最后一个 `|` 后的译文；偏移、原文字段、`len`、记录号和文件头注释不能改。
- FHN 文本字段固定为 `0x40` 字节，记录尾部参数必须保持；译文超出容量时精简措辞，不改槽位或偏移。
- `{G01}`、`{H06}`、`{V10}`、`{B06}`、`{T}`、`{S5}` 等占位符是控制码，数量、拼写、大小写和相对位置必须与原文一致。不要把它们翻译成文字。
- `ui` 文件由 `tools/ui_write.py` 按固定偏移回写；不要把 UI 候选当作 FHN 记录或普通 SPL 记录处理。

### MOVIMAGE 影片字幕

字幕候选使用时间码和译文：

```text
0065:0136|相传，
```

- 只编辑 `|` 后的文字；时间码、文件头元数据、`#####` 终止标记和记录数量不可改。
- 保持字幕块的分行、顺序和节奏；相邻字幕行属于同一旁白时要结合上下文校对。
- 影片字幕使用独立的 XOR/固定长度工具链，不要用 `text_7w.py write` 或 UI 写回器处理。

## 翻译与校对标准

- 先根据日文原文、上下文和角色关系确定含义，再审查旧译文；旧译文不是权威。语序生硬、主语错位、指代不清或衔接不自然时直接重译。
- 对话要符合角色语气，叙述、帮助和系统说明要简洁清楚。可根据上下文补足省略的主语、承接和时态，但不得凭空添加剧情信息。
- 跨行或跨节点句子保持完整语法。上一行以逗号、顿号或未完短语结束时，下一行自然承接；不要每行强行加句号，也不要重复主语、宾语或标点。
- 保留引号、按钮符号、方向键、箭头、数字、等级、单位、时间码和列表关系；中文标点可按语境调整，但不能改变功能含义。
- 专有名词、菜单项和同一概念在全文件中统一；术语表优先于旧译文、机器译文和临时译法。
- 原文疑似截断、乱码、语义无法判断或术语表冲突时，保留可确认部分并记录待确认项，不通过修改结构或猜测掩盖问题。

## 控制符与结构保护

控制符必须“原样保留、不可删除、不可改写”。编辑前后逐条检查 `\n`、`\r` 转义、`%...%`、`$...`、FHN 占位符、按钮/方向符号、箭头、数值占位、时间码及项目实际出现的控制字节表示。控制标记的数量、拼写、大小写和相对位置必须一致，不要把转义形式变成真实换行，也不要把控制符翻译成文字。

NHT 的 `[link]` 和 `[keep]` 是结构节点，绝不触碰。FHM 的空记录、`[tail:n]` 和子资源元数据必须保留。FHN 字段后的记录尾部参数不可改。不要用宽泛的全局替换处理控制符或术语；修改后必须使用对应结构化工具验证。

## 完成前的检查

保存候选稿前完成以下检查：

1. 抽查每个修改段落、条目、界面流程或字幕块的前后记录，确认句子连贯，人物、地点、菜单和时间顺序没有错位。
2. 按 TSV 搜索本次涉及的日文术语，逐项检查译文是否采用项目统一译名；长词、带后缀地名和同音人名尤其要查。
3. 对比修改前后的字段，确认只变更译文：索引、偏移、长度、记录号、NHT link/keep、FHM tail 和字幕时间码均未变。
4. 核对控制符、占位符、按钮符号、数字、格式标记和 `#####` 没有丢失、增删或错位。
5. 用对应工具写到临时输出或 `work/build`，不要覆盖原始文件：

   ```powershell
   python tools\text_7w.py write <原.spl> <候选.txt> <临时.spl>
   python tools\text_7w.py nht write <原.nht> <候选.txt> <临时.nht>
   python tools\text_7w.py fhm write <原.fhm> <候选.txt> <临时.fhm>
   python tools\fhn_text_7w.py write --unpacked unpacked\CDIMAGE_FULL --translation work\translation\fhn --original-tree temp\CDIMAGE_ORIGINAL
   python tools\ui_write.py --unpacked unpacked\CDIMAGE_FULL --original-tree temp\CDIMAGE_ORIGINAL
   python tools\text_7w.py elf write <原ELF> <候选.txt> <临时ELF> --manifest <ELF清单.tsv>
   python tools\movie_subtitle_7w.py write-all unpak\MOVIMAGE.BIN work\translation\movie_subtitles <临时MOVIMAGE.BIN> --map work\font\sub0_map.tsv
   ```

   以实际项目文档和命令帮助为准补齐参数。重点查看 `overflow`、`unencodable`、`mismatch`、`ignored`、`relocated` 和 `skipped`；任何异常都要回到对应译文处理，不能静默忽略。
6. 对 SPL/NHT/FHM/ELF/FHN 或字幕输出重新提取或解析，确认中文可读、图片区和节点未丢失，固定槽没有越界；原样候选的 round-trip 应尽量保持字节一致。

完成时简要报告改动文件、未决语义问题和工具报告中的异常数量。
