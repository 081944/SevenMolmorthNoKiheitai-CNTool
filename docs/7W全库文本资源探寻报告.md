# 7W 全库文本资源探寻报告

本文档记录对整个解包仓库 `unpacked/CDIMAGE_FULL`（2718 个文件）的一次系统
性"额外文本"探寻。目的是查清：除已提取的 321 个 `.spl` 剧情脚本之外，还有
没有其他含真实可译文本的资源。

## 探寻方法

对每个非图像/字库文件，用两类判据鉴别是否含"真实散文文本"：

1. **宽松判据（粗筛）**：统计含 SJIS 双字节候选的行数与字符量。这会产生大量
   误报——二进制纹理/压缩数据被误判为"日文"（如 `ﾍﾍﾍﾍ`、`UUUU`、`""匯;C膀`
   这类乱码其实是位图原始字节）。
2. **严格判据（定论）**：只在满足以下条件的行才算"真文本"：
   - 解码后含平假名且不少于 3 个；
   - 平假名+汉字占比 ≥ 50%（排除纯片假名填充与纹理）；
   - 字符多样性足够（排除重复单字噪声）。

严格判据下的正例需再经人工抽样核对。

上述句子池判据不适用于 FHN：FHN 的界面文案按资源偏移表、固定字段长度和
记录尾部结构判定，单字标签（如 `位`、`歳`）也可能是有效文本。

### `.nht` 帮助文本表结构（新确认）

`help/endless.nht`（90 条可编辑帮助条目，另含 42 张 ITE 图）与
`help/rpg.nht`（49 条可编辑帮助条目，另含 29 张 ITE 图）是"帮助文本 + ITE
图片"的复合容器。**文件首 `u32` 是图片数，不是条目数**；文本条目数需从
`0x04` 起连续读取偏移、遇 0 结束。每个普通条目含 `0x40` 字节标题槽及正文，
正文以"节点"流组织（见下）。完整结构见 `docs/NHT格式与重建说明.md`。

```text
0x000  u32   image_count
0x004  u32   text_offset[]（以首个 0 终止）
0x400  u32   image_offset[image_count + 1]（image_offset[0]=0）
0x804  文本条目区：每条 title[0x40] + body 节点流
       后接 ITE 图片区
```

正文是含内联控制码的富文本，用 "节点" 建模范式建模：

- `link`（热字链接）：字节序列
  `…28 00 00 80 16 <id:u16> <len:u8> ff ff <标题> 17 <len2:u16> 13 16 14 00 00 00 80`，
  用于跳转到其它帮助条目，标题为可读日文（如 `王の間`、`貢献度`）；
- `text`：连续可译的 CP932 文本（含半角片假名、ASCII）；
- `keep`：换行 `\n`、NUL 填充、`\x15` 等控制字节（结构，只读保留）。

工具 `text_7w.py nht extract / write` 已按上述节点建模，回写时 `text` 可译、
`link`/`keep` 原位保留，两个 `.nht` 均通过 `SHA256` 无损 round-trip 验证。
用法与候选格式见 `docs/工具与产物目录规范.md`。

示例（`endless.nht` 前几项）：

```text
［01］はじめに
［02］ゲームの説明
［03］基本的な遊び方（準備編）
［04］基本的な遊び方（遠征編）
……
```

### `common.fhm` 界面/命名文本（新确认）

`chiibaya/common/common.fhm`（约 1 MB）是一个**多子资源容器**：

```text
u32  子资源数量 (3)
u32 * 3  各子资源绝对偏移
[0] SFO 字库（约 1 MB）
[1] SFO 字库（约 6 KB）
[2] 文本子资源：u32 数量 + NUL 结尾 CP932 字符串
```

文本子资源位于第 3 个子资源（偏移 `0xFD8E0` 起，长 11344 字节）。真实结构是
`u32 数量(550) + 运行时指针缓存[550]（磁盘全零） + NUL 结尾 CP932 字符串[550]`
+ **5 条无索引尾部字符串**：职业名（戦士/騎士/幻術師…）、专属人名、地名，以及
含 `%d`/`%s` 的记录/评价格式化消息（如 `評価BEST20第%d位にランクインしました`）。
550 条主记录中 479 条非空，其余为空槽；提取/回写按**真实记录号**保留空槽。
重建器会整体重排字符串池并在需要时扩展容器、重算后续子资源绝对偏移（不再受
原槽长限制）。工具 `text_7w.py fhm extract / write` 已实现，`common.fhm` 通过
`SHA256` 无损 round-trip 验证。完整结构见 `docs/FHM格式与重建说明.md`。

### `takeshi/screen` FHN 界面固定字段（新确认）

这 42 个 FHN 资源不是普通的 NUL 结尾字符串池。非 ITE 资源中存在固定
`0x40` 字节字段，字段后通常跟随 `0x18` 字节记录尾部；同一字段内还可能有
多个由 NUL 分隔的文本/控制片段。`tools/fhn_text_7w.py` 按 FHN 资源偏移表
跳过 `ITE\0`/`GIM\0` 图片资源，只在非图片资源中识别该记录结构，避免把压缩图像
字节误报成日文。

当前原版解包结果为 40 个候选文件、222 条记录。候选中的 `{Z}` 表示字段内部
真实 NUL，`{Cxx}` 表示裸字段控制字节；二者都必须在译文中保留。`mov.fhn` 和
`opt.fhn` 不重复写入；`kimura/ef/*.fhn` 当前没有可靠的句子文本。

## 被排除的疑似资源（严格判据下为误报）

以下类型此前在旧分类文档中被判"动画/数据/图像"，本次严格扫描**确认其不
含可翻译的成句文本**，均为二进制/纹理/名字数据：

| 类型 | 规模 | 结论 |
| ---- | --- | ---- |
| `.pma`（`rpgdata/map/*`） | 166 | 地图容器，含 GIM 图像块，无成句文本 |
| `.aal`（`rpgdata/anime/*`） | 828 | 动画事件，无成句文本 |
| `.fhn`（`kimura/ef/*`） | 46 | 演出/特效资源，无成句文本 |
| `.fit`（`takayama/aap/*`） | 486 | 演出资源，无成句文本 |
| `.mdt`（`battle_dat/*`） | 18 | 战斗数据，无成句文本 |
| `member.smd`（`battle_dat/commit/`） | 1 | `SMD\0` 头，紧凑拼接的随机角色名池（无分隔符），属数据非句子 |
| `chiibaya/rpgcommon/common.fhm` | — | 与 `common/common.fhm` 不同，严格扫描 0 文本区 |

> 注意：宽泛的 "SJIS 候选量" 排名会把 `.pma`/`.aal`/`.fhn` 排在前面，
> 但它们经人工抽样与严格判据核对后都是位图/压缩噪声，**不能**用
> `text_7w.py extract` 直接当作文本提取。

## 结论

除了 321 个 `.spl` 剧情脚本，全库还确认有 **4 类可靠的额外文本资源**：

- `help/endless.nht`（90 条剧情/游玩帮助条目）
- `help/rpg.nht`（49 条 RPG 帮助条目）
- `chiibaya/common/common.fhm`（界面记录文案）
- `takeshi/screen/*.fhn`（界面固定字段文案）

这四类都是**可译文本**，应在翻译计划中纳入。`.spl` 之外的大多数"高字符量"
文件（`.pma`/`.aal`/`.fit`/`.mdt`，以及 `kimura/ef/*.fhn`）经严格核验为
二进制或数据，不属句子文本。

## 附带说明

本报告早期的宽松扫描（一次性 `temp/probe_text*.py` 分析脚本，现已移除）会在
`.pma`/`.aal` 等文件上产生大量 SJIS 误报，仅用于初步定位，不作为文本判定
依据；定论以本文档的严格判据与人工抽样核验为准。文本资源的正式提取一律使用
`tools/text_7w.py` 的结构化解析（`spl`/`nht`/`fhm`），不再使用宽松字节扫描。
