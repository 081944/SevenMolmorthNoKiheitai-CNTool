# 7W 界面错字与漏字动态定位方法

本文记录如何从屏幕异常字反查游戏原本要显示的字符，并定位到 ELF、资源或存档。
实测案例是编成界面的“回复力 18权”和“15授 骑士”。

## 核心判断

汉化字库把中文分配到原字库的双字节槽位。若原版单字没有重新编码，它会继续使用
原日文 CP932 字节，但该字节在新字库中可能已经被分给另一个中文，于是屏幕显示错字。

```text
8E A9 -> 原版 CP932：自 -> 当前中文字库槽位：权 -> 屏幕：权
```

这种情况不是控制符被识别成文字。常见问题分为：

| 类型 | 证据 | 处理 |
| --- | --- | --- |
| 漏重编码单字 | 合法 CP932 双字节，常有独立 NUL 结尾 | 加入候选，随字库重新编码 |
| 控制符 | 位于长字符串内部，后接参数，解析器有专门分支 | 修正提取/写回，保留控制结构 |
| 存档/动态文本 | 字符串在堆、UI 对象或存档缓冲区，不在静态 ELF | 追踪来源指针和存档字段 |

## 证据链

```text
观察界面 -> 查当前字库槽位 -> PCSX2 搜索运行时字节
-> 读取前后文和边界 -> 按原版 CP932 解码
-> 对照原始文件 -> 判断 ELF/资源/存档来源
-> 热补丁验证 -> 加正式候选 -> 完整构建 -> 冷启动回归
```

至少闭合三项证据：运行时实际字节、原版 CP932 字符、字段语义。

## 1. 记录界面上下文

记录界面、字段、异常字和相邻文本。例如：

```text
编成 -> 人物介绍 -> 回复力 18权
```

相邻字段能帮助判断“自/列”这类属性类型或“歳”这类年龄单位。角色名要单独考虑
存档来源，不能套用单位表的结论。

## 2. 从错字反查槽位

当前构建的映射文件是：

```text
work/font/char_to_slot.csv
work/font/sub0_map.tsv
```

查询屏幕上的错字：

```powershell
Select-String -Path work\font\sub0_map.tsv -Pattern '^权\t'
```

例如结果为 `权  8EA9`，则搜索目标是字节 `8E A9`。映射每次完整分配后都可能改变，
不可长期硬编码。

## 3. 用 PCSX2 MCP 搜索内存

连接 DebugServer：

```json
{"mode":"auto","debug_port":21512,"pine_port":28011}
```

对应 MCP 为 `pcsx2_connect`。Pine 超时不影响 DebugServer 的内存、断点和反汇编。

搜索时包含 NUL 或上下文：

```json
{"pattern":"8E A9 00","start":"0x00100000","end":"0x02000000","max_results":50}
```

对应 MCP 为 `pcsx2_find_pattern`。候选命中后读取前后至少 `0x20` 到 `0x80` 字节：

```json
{"address":"0x0030FC80","length":64,"format":"hexdump"}
```

对应 MCP 为 `pcsx2_read_memory`。重点检查：

- 目标双字节后是否直接跟 `00`；
- 前后是否有固定短字符串或指针表；
- 数字是否在另一个缓冲区，目标字符只是单位/类型；
- 地址是否是 ELF 静态区，还是进界面后才出现的堆地址。

本次动态证据：

```text
EE 0x0030FC96: 8E A9 00    原版“自”
EE 0x0030FC9C: 97 F1 00    原版“列”
EE 0x003341F0: 8D CE 00    原版“歳”
EE 0x003341F8: 94 4E 00    原版“年”
EE 0x00334200: 93 FA 00    原版“日”
EE 0x00334208: 95 AA 00    原版“分”
EE 0x00334210: 95 62 00    原版“秒”
```

这些是独立短字符串，不是数字缓冲区越界。

## 4. 按原版 CP932 解码

```powershell
$cp932 = [Text.Encoding]::GetEncoding(932)
$cp932.GetString([byte[]](0x8E,0xA9)) # 自
$cp932.GetString([byte[]](0x8D,0xCE)) # 歳
```

当前字库映射说明“为什么画成错字”，原版 CP932 说明“原游戏本来是什么字”。

| 屏幕 | 字节 | 原版 | 语义 | 修复 |
| --- | --- | --- | --- | --- |
| 权 | `8E A9` | 自 | 自回复类型 | 自 |
| 授 | `8D CE` | 歳 | 年龄单位 | 岁 |

## 5. 判定数据来源

### ELF 静态字符串

用 ELF `PT_LOAD` 关系换算：

```text
file_offset = runtime_address - (p_vaddr - p_offset)
```

本版本实测装载偏差为 `0xFF000`：

```text
0x0030FC96 -> ELF 0x00210C96
0x003341F0 -> ELF 0x002351F0
```

必须再读取干净 ELF 核对：

```powershell
$b=[IO.File]::ReadAllBytes('work\elf\SLPS_250.25')
$o=0x2351F0
'{0:X2} {1:X2} {2:X2}' -f $b[$o],$b[$o+1],$b[$o+2]
```

### 加载资源

堆地址每次可能变化，不能直接换算成 ELF。应读取唯一上下文，在干净解包树中搜索，
比较资源偏移和运行时缓冲区，并在必要时对缓冲区设置 read watchpoint。

### 存档/动态文本

换存档后内容变化、新建存档后旧字消失，或地址位于存档读取缓冲区，都说明应追踪
存档字段。ASCII 角色名异常通常与中文字库槽位无关。

## 6. 区分文字和控制符

更像真实文字的证据：合法 CP932 双字节、后接 NUL、原版同位置有该字、指针直接传入
测宽/绘制函数，替换后只改变一个字。

更像控制符的证据：位于长字符串内部、后接长度/颜色/坐标参数、解析器跳转专门分支，
修改后出现换行错乱、颜色错乱、指针错位或卡死。

最终应看该字节如何被读取和使用，而不是只看数值范围。

## 7. 先热补丁再正式修改

从当前 `sub0_map.tsv` 查目标字符槽位后，用 `pcsx2_write_memory` 写入运行时地址。
某次旧构建验证过：

```json
{"address":"0x0030FC96","data":"91DE"}
{"address":"0x003341F0","data":"8C57"}
```

若画面立即变成“回复力 18自”或“15岁”，定位成立。新字符加入后槽位可能重排，
本次最终“自”为 `91DF`，因此旧热补丁不能复制到新构建。

## 8. 加入 ELF 正式候选

确认文件偏移后编辑 `work/translation/elf/slps_250.25.txt`：

```text
[0905] @0x210C96 len=2 | 自|自
[0906] @0x210C9C len=2 | 列|列
[0912] @0x2351F0 len=2 | 歳|岁
[0913] @0x2351F8 len=2 | 年|年
[0914] @0x235200 len=2 | 日|日
[0915] @0x235208 len=2 | 分|分
[0916] @0x235210 len=2 | 秒|秒
```

即使“年/日/分/秒”字形不变，也必须加入候选，因为原版 CP932 槽位仍要重新编码。

## 9. 完整构建和验证

使用干净原始树，保证先恢复日文源再回写：

```powershell
python tools\build_all.py --both --original-tree temp\original_build_tree
```

本次最终映射和 ELF 字节：

```text
分=89D5  列=89D9  岁=8C57  年=8C86
日=8E6B  秒=90D0  自=91DF

ELF 0x210C96: 91 DF 00
ELF 0x210C9C: 89 D9 00
ELF 0x2351F0: 8C 57 00
ELF 0x2351F8: 8C 86 00
ELF 0x235200: 8E 6B 00
ELF 0x235208: 89 D5 00
ELF 0x235210: 90 D0 00
```

最后必须冷启动新 ISO，重新进入目标界面，检查多个角色、相邻数字和布局。旧 PCSX2
进程中的热补丁只证明定位正确，不证明磁盘产物已生效。
