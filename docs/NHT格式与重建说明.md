# NHT 格式与可变长重建说明

本文记录《七人之勇者》PS2 版 `help/endless.nht` 与 `help/rpg.nht` 的完整容器
结构、正文节点规则和 `tools/text_7w.py` 的可变长重建方法。结论以原版
`temp/CDIMAGE_ORIGINAL` 文件、PCSX2 DebugServer 检查和 IDA Pro 静态分析环境
为依据。

## 1. 总体结构

NHT 是“帮助文本 + ITE 图片”的复合容器，固定头部大小为 `0x800`：

```text
0x000  u32 image_count
0x004  u32 text_offset[]       # 文件绝对偏移，以首个 0 终止
       zero padding to 0x400
0x400  u32 image_offset[image_count + 1]
       # image_offset[0] 固定为 0
       # image_offset[1..image_count] 指向 ITE\0
       zero padding to 0x800
0x800  4 字节零填充
0x804  文本条目区
       ITE 图片区
```

文件首个 `u32` 不是文本条目数量，而是图片数量。文本条目数量必须从
`0x04` 开始持续读取偏移，遇到 0 才结束。旧工具把两者混为一谈，因此漏掉
后半段帮助条目，又把最后一条正文一直读到文件末尾，将 ITE 像素数据误识别为
数万个文本节点。

两个原版样本的边界如下：

| 文件 | 文件大小 | 图片数 | 文本偏移数 | 第一条文本 | 第一张 ITE |
| --- | ---: | ---: | ---: | ---: | ---: |
| `endless.nht` | `0x76550` | 42 | 91 | `0x804` | `0xF650` |
| `rpg.nht` | `0x5F460` | 29 | 50 | `0x804` | `0x65D0` |

文本偏移表和图片偏移表都是文件绝对偏移，严格递增。每个有效图片偏移处均为
`49 54 45 00`（`ITE\0`）。第一张图片的偏移同时是整个文本区的唯一可靠结束
边界。

## 2. 文本条目

`text_offset[0]` 是内部根/目录条目，包含帮助页菜单的热链接；现在也会被提取，
因此用户可编辑的帮助条目范围从索引 0 开始。条目 `i` 的范围为：

```text
start = text_offset[i]
end   = text_offset[i + 1]
# 最后一项：end = image_offset[1]
```

普通条目内部布局为：

```text
start + 0x00  char title[0x40]   # CP932 标题，NUL 结尾，槽内余字节保留
start + 0x40  byte body[]        # 正文节点流
end           下一条目或第一张 ITE
```

标题槽固定为 `0x40` 字节。旧实现使用十进制 70（`0x46`），会从 CP932 双字节
字符中间进入正文，造成开头字符丢失。正文长度由相邻结构偏移决定，不能通过
寻找长零区猜测。

### 2.1 正文节点

正文不是单一 NUL 字符串，而是以下节点的有序流：

- `text`：可解码 CP932 文本，可替换并改变长度；
- `link`：带固定标记和目标标题的热字链接，只替换其中的显示标题，控制字段、
  目标编号和内部 `_1`/`_2` 路由后缀原样保留；
- `keep`：控制字节、终止符、对齐和未知字段，原样保留。

提取文件中的 `[title]`、`[text:n]` 和 `[link:n]` 均支持双栏翻译；`[keep]` 是
只读结构。写回器只改标题槽或链接标题，不改链接控制字段和跳转关系。节点号是
当前条目内同类节点的序号，不是所有节点的总序号。

## 3. 可变长重建

`rebuild_nht()` 按以下流程重建整个容器：

1. 校验两个偏移表、文本边界、图片边界和每个 `ITE\0` magic。
2. 保留每条目的 `0x40` 标题槽，结构化解析根目录和正文节点。
3. 仅替换指定标题、`text` 节点和链接显示名；不可编码文本保留原字节并计数。
4. 重新串接条目正文。新内容未超过原条目容量时补零并维持原大小；超过时把
   条目扩展到 `0x10` 对齐。
5. 重算并写回全部文本绝对偏移。
6. 将整个 ITE 图片区整体后移，重算 `image_offset[1..image_count]`；所有图片
   内容逐字节复制。

因此正文译文不受原节点 `len` 限制；标题槽仍受 `0x40` 固定容量限制，链接标题可
随正文区一起增长。菜单目录（根条目）也会随候选文件一起回写。

## 4. 工具用法

```powershell
python tools\text_7w.py nht extract `
  temp\CDIMAGE_ORIGINAL\seven_data_link\help\endless.nht `
  work\text\nht\endless.nht.txt

python tools\text_7w.py nht write `
  temp\CDIMAGE_ORIGINAL\seven_data_link\help\endless.nht `
  work\text\nht\endless.nht.txt `
  work\text\nht\endless.rebuilt.nht
```

翻译采用双栏写法；只有第二个 `|` 后的内容会作为译文：

```text
[text:0] len=34 | 原文 | 任意长度译文
[title] len=8 | 基本操作 | 基本操作
[link:0] len=31 | 基本操作 | 基本操作
[keep] n=3
```

根条目 `0000` 就是帮助目录。链接标题中可能带有 `_1`、`_2` 等内部去重后缀，
候选文件只显示可见标题，写回时会自动把原后缀接回译文。

旧版候选由错误的 `+70` 正文起点生成，正文节点和末条边界均不可信。写入器会
检查每条头部的 `body=0x...`，检测到旧偏移时明确拒绝并要求用新解析器重新提取；
不会尝试把旧节点猜测映射到新节点。

## 5. 验证结果

- `endless.nht` 结构化提取 90 个可编辑条目、42 张图片；原样回写 SHA256 与
  原版一致：`3FEDAC61D24C1D5A1AA2CBD204F5E9A470092B78D3551BE48BAE0A601F6DD32B`。
- `rpg.nht` 结构化提取 49 个可编辑条目、29 张图片；原样回写 SHA256 与
  原版一致：`F790D7E206C4903D0DB8D792FB483A4F26C6F4482EC0FFD34C8B4FB7DB991410`。
- 将 `endless` 条目 1 的首个文本节点扩到 400 字节后，文件和第一张 ITE 均
  后移 368 字节；重新解析可读回完整 400 字节，搬移后的整个 ITE 区与原版
  逐字节相同。
- 旧版最后一条产生的数万伪节点已消失，首个正文字符不再因 `+70` 错位丢失。

## 6. PCSX2 与 IDA 证据边界

PCSX2 DebugServer 当前连接正常，但游戏仍停留在对话/SPL 场景。对 EE 内存
`0x00000000..0x02000000` 搜索 `endless.nht` 唯一头部序列
`2A 00 00 00 04 08 00 00 D0 10 00 00` 无命中，说明当前场景没有加载帮助 NHT；
因此本文不虚构 NHT 运行时基址或加载器断点。

IDA Pro 数据库为 `work/elf/SLPS_250.25.i64`。此前 SPL/FHM 调试已确认游戏对
这类资源采用“磁盘相对/绝对偏移表，加载后直接按指针消费”的模式；NHT 的双表
布局则由两个原版样本、全部边界 magic、无损 round-trip 和增长后可逆解析共同
证明。要取得 NHT 专属的运行时加载器证据，需要先在原版游戏进入帮助界面，使
NHT 实际驻留 EE 内存，再对头部或第一张 ITE 设置读 watchpoint。
