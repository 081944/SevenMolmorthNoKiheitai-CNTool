# 工具与产物目录规范

本文档是 7W 工程的 **工具命令手册** 与 **产物/临时目录规范** 的权威来源。
它收纳了原 `tools/README.md` 与 `work/README.md`（已删除，内容并入本文档）。

工程按"研究结论"与"操作规范"拆分文档：

- 资源格式、已确认/高概率分类等 **分析结论** → `docs/7W文本图片字库分类说明.md`
- 全库"额外文本"探寻结果 → `docs/7W全库文本资源探寻报告.md`
- 解包步骤 → `docs/CDIMAGE解包说明.md`
- 字库 SFO 解析进度 → `docs/font16.sfo-7w.md`、`docs/common_fhm_sub0字库.md`
- 一键构建（字体+回写+repack） → **`tools/build_all.py`**（见"一键构建"一节）
- 工具怎么用、产物放哪里 → **本文档**

## 目录规范

`temp/` 与 `work/` 分离：`temp/` 放临时/中间产物（可随时删除），`work/` 放
正式工作产物。

### `work/` 正式产物

| 目录 | 用途 |
| ---- | ---- |
| `work/text/raw/` | 提取的原始文本（`text_7w.py extract` 输出，321 个 `.spl` → 321 个 `.txt`） |
| `work/text/nht/` | 帮助文本 `.nht` 的提取结果（endless / rpg）与回写成稿 |
| `work/text/fhm/` | 界面/命名文本 `.fhm` 的提取结果（common）与回写成稿 |
| `work/text/translated/` | 已翻译完成的 `.spl` 文本（与 `raw/` 同名对应，成稿） |
| `work/image/` | 导出的原始图片资源（可重新生成） |
| `work/imageedit/` | 编辑后准备回写的图片资源 |
| `work/imagealpha/.state/` | GIM 原透明度快照和编辑标记，原路径 PNG 反写时自动读取，需随改图保留 |
| `work/translation/` | 翻译过程文件（术语表、对照表、校对、脚本写回说明等） |
| `work/translation/fhn/` | 已确认 UI FHN 固定字段文本候选与译文 |
| `work/font/` | 字库相关产物（字体位图导出、回写等） |
| `work/report/` | 聚合报告（manifest、资源分类 CSV 等） |

### `temp/` 临时目录

- 脚本运行产生的中间文件、验证用的副本、候选草稿等都放这里。
- 目录内容随时可删除，不要依赖其中的产物。
- 不会提交进正式产物，也不会被回写流程引用。

## text_7w.py —— 统一文本工具

三个子命令，共享同一套偏移/行定义，`extract` 输出的候选格式可直接交给
`write` 回写。

### 1. scan —— 资源分类

```powershell
python tools\text_7w.py scan unpacked\CDIMAGE_FULL work\report\resource_report.csv
```

按 magic 全量清点资源：`GIM`(图)、`ITE`、`KWSM`、`PS2D`、`plain-01`(纯文本脚本)。
`GIM`/`ITE`/`KWSM`/`PS2D` 不能直接当文本处理（会把图像数据误判成 Shift-JIS），
仅对 `plain-01` 标记候选文本。

### 2. extract —— 行级清洗提取

**单文件**：

```powershell
python tools\text_7w.py extract `
  unpacked\CDIMAGE_FULL\seven_data_link\rpgdata\output\文件.spl `
  work\text\raw\文件.txt
```

**全量批量**（321 个 `.spl`）：

```powershell
python tools\text_7w.py extract `
  unpacked\CDIMAGE_FULL work\text\raw --manifest work\report\spl_manifest.csv
```

提取先完整解析 SPL 头、VM 指令区、目录和类型化数据块，仅从 type-3/type-10
字符串池按 `0x00`/`0x0A`/`0x0D` 等分隔符逐行切分，避免把二进制结构字段误当
文本。逐行保留原始偏移和旧长度，用作候选行身份校验而非容量限制。`--min-chars`
（默认 2）可调每行最少双字节字符数。输出到
`work/text/raw/`（每脚本一个 `.txt`），聚合清单在 `work/report/spl_manifest.csv`。

原版结构化扫描结果：321 个脚本，17,766 行（包含旧启发式扫描漏掉的池内短文本）。

### 3. write —— 回写

```powershell
python tools\text_7w.py write `
  <原.spl> `
  work\text\translated\候选.txt `
  work\text\translated\<新>.spl
```

候选文件使用 `extract` 的输出格式（`[行号] @0x偏移 len=旧长度 | 原文|译文`）。
写入时会重建整个可变长字符串池、重算 type-9/type-11 引用并移动后续块，译文
不再受原 `len` 限制。工具同时校验左侧原文；旧候选偏移错误时可按原文自动
重定位，二进制假阳性会计入 `ignored` 而不写入。中文字使用
`work/font/char_to_slot.csv` 的字库槽位编码。完整格式见
`docs/SPL格式与重建说明.md`。

## 帮助文本 `.nht`

`help/endless.nht` 与 `help/rpg.nht` 是位于
`unpacked/CDIMAGE_FULL/seven_data_link/help/` 的帮助文本/图片复合容器（含剧情
介绍、游玩说明与系统帮助）。固定 `0x800` 头部包含以 0 终止的文本绝对偏移表
和 ITE 图片绝对偏移表；文件首个 `u32` 是图片数，不是文本条目数。每个普通
文本条目含 `0x40` 字节标题槽及正文。正文内含内联热字链接（跳转到其它条目）
与若干控制字节，工具按"节点"建模：
`text`（可译）、`link`（热字链接，只读保留）、`keep`（控制字节/填充，只读）。

提取（逐节点可读）：

```powershell
python tools\text_7w.py nht extract `
  unpacked\CDIMAGE_FULL\seven_data_link\help\endless.nht `
  work\text\nht\endless.nht.txt
```

候选格式（`[text:N] len=原字节数 | 文本`，link/keep 只读）：

```text
### 条目 0003 标题=基本的な遊び方（準備編） body=0x1460 len=736
[link] 王の間
[text:0] len=34 | 」などで見ることができる画面右上の
[link] 貢献度
[text:2] len=16 | を表しています。
```

回写（以节点为单元，`text` 可任意增长；link/keep 原样保留）：

```powershell
python tools\text_7w.py nht write `
  unpacked\CDIMAGE_FULL\seven_data_link\help\endless.nht `
  work\text\nht\候选.txt `
  work\text\nht\输出.nht
```

回写器会重建完整文本区、重算所有文本偏移，并在条目增长时整体搬移 ITE 图片区
及重算图片偏移。已用原样 round-trip 验证两个 `.nht` 均 `SHA256` 无损，400
字节超长节点也可重建和回读。旧版 `+70` 正文起点候选必须重新提取。完整结构见
`docs/NHT格式与重建说明.md`。中文回写仍依赖相应字库槽位；不可编码字符会保留
原文并计入警告。

## 界面/命名文本 `.fhm`

`chiibaya/common/common.fhm` 是一个**多子资源容器**：前两个子资源为 SFO 字库，
最后一个子资源为**文本表**。其结构为 `u32 数量 + u32 运行时指针缓存[数量] +`
`NUL 结尾 CP932 字符串[数量]`（含职业名、专属人名、地名，以及含 `%d`/`%s`
的记录/评价格式化消息）。完整结构见 `docs/FHM格式与重建说明.md`。

提取（每个字符串一行，序号与回写严格对应）：

```powershell
python tools\text_7w.py fhm extract `
  unpacked\CDIMAGE_FULL\seven_data_link\chiibaya\common\common.fhm `
  work\text\fhm\common.fhm.txt
```

检查是否有 FHM 漏提时，可对 `seven_data_link` 目录批量提取并生成清单：

```powershell
python tools\text_7w.py fhm extract `
  temp\original_build_tree\seven_data_link work\text\fhm `
  --manifest work\report\fhm_manifest.csv
```

清单会同时记录 `text` 和 `no-text` 文件及拒绝原因；输入应使用 pristine 日文
树，避免已写入中文字库的 `unpacked` 字节被当成原文。

候选格式：

```text
[text:0] len=4 | 戦士
[text:9] len=10 | アーチャー
[text:33] len=40 | 評価BEST20第%d位にランクダウンしました。
```

回写会重建完整字符串池，支持超过原槽长度的译文；文本块增长时会扩展 FHM、
更新后续子资源绝对偏移，两个字库子资源内容保持不变：

```powershell
python tools\text_7w.py fhm write `
  unpacked\CDIMAGE_FULL\seven_data_link\chiibaya\common\common.fhm `
  work\text\fhm\候选.txt `
  work\text\fhm\输出.fhm
```

已用原样 round-trip 验证 `common.fhm` 为 `SHA256` 无损。提取工具会结构化校验
文本子资源，不再把 `rpgcommon/common.fhm` 的数值块误判成文本。磁盘上的指针
缓存为零，PCSX2 运行时由加载器填入绝对字符串地址；回写按真实记录号重建。

## 字库工具

### 存档兼容的稳定槽位分配

`build_all.py` 默认使用 `font_alloc_stable_7w.py` 更新
`work/font/char_to_slot.csv`：已有字符的 `index/lead/trail` 永远不变，暂时不用的
字符也会保留，新字符只追加到未使用槽位。这样存档中的姓名/地名 CP932 双字节码
不会因为校对增加字符而改变含义。请把该 CSV 与发布的字库一同归档；只有明确不
考虑旧存档时才使用 `build_all.py --fresh-font-map`。

单独预览新增分配：

```powershell
python tools\font_alloc_stable_7w.py --charset work\font\char_set.txt --dry-run
```

### font16.sfo（aria 主字库，16x16）

```powershell
python tools\font_sfo_7w.py inspect `
  unpacked\CDIMAGE_FULL\seven_data_link\arita\font16.sfo
```

已确认的字库之一是 `unpacked\CDIMAGE_FULL\seven_data_link\arita\font16.sfo`。
`font_sfo_7w.py` 支持 `inspect` / `export` / `atlas` / `rebuild` 四个子命令，
可将字形导出为 PNG 像素图（`export`）并支持 PNG 回写（`rebuild`，双字节区已
通过 SHA256 无损测试）。完整用法见 `docs/font16.sfo-7w.md`。

### common.fhm sub0（对白渲染字库，24x24）

> ⚠️ 对白/剧情文本渲染**实际使用** `chiibaya/common/common.fhm` 内的 sub0 字库，
> 不是 aria/font16.sfo。汉化对白须写入 sub0。完整格式见
> `docs/common_fhm_sub0字库.md`。

```powershell
# 检查 sub0 结构 / 锚点
python tools\font_sub0_7w.py inspect `
  unpacked\CDIMAGE_FULL\seven_data_link\chiibaya\common\common.fhm

# 导出单字形核验
python tools\font_sub0_7w.py export `
  unpacked\CDIMAGE_FULL\seven_data_link\chiibaya\common\common.fhm `
  --idx 907 --out temp\g.png

# 写入中文字形（映射表格式：字符<TAB>CP932十六进制）
python tools\font_sub0_7w.py write `
  unpacked\CDIMAGE_FULL\seven_data_link\chiibaya\common\common.fhm `
  work\font\common_sub0_ch.fhm --map work\font\sub0_map.tsv

# 同时写入 font16.sfo（两套字库都更新，防 UI 文本走另一渲染路径）
python tools\font_sub0_7w.py write `
  unpacked\CDIMAGE_FULL\seven_data_link\chiibaya\common\common.fhm `
  work\font\common_both_ch.fhm --map work\font\sub0_map.tsv `
  --target both --font16 unpacked\CDIMAGE_FULL\seven_data_link\arita\font16.sfo

# 单写 font16（fhm 位置传 font16.sfo）
python tools\font_sub0_7w.py write `
  unpacked\CDIMAGE_FULL\seven_data_link\arita\font16.sfo `
  work\font\font16_ch.sfo --map work\font\sub0_map.tsv --target font16

# font16 也可 inspect / export
python tools\font_sub0_7w.py inspect `
  unpacked\CDIMAGE_FULL\seven_data_link\arita\font16.sfo --target font16
```

写入只覆盖目标槽位（sub0 每字形 288 字节、font16 每字形 128 字节），文件大小
保持不变（common.fhm=`0x100530`、font16.sfo=`0x6FE10`）；TTF 字形默认取自
系统 msyh/simhei 等，可用 `--font` 指定。`--target` 取值：`common`（默认，
只写 sub0）/ `font16`（只写 font16）/ `both`（同时写，需 `--font16` 指定
font16.sfo 路径，输出 `输出名` + `输出名_font16.sfo`）。

> 说明：字形**候选**扫描/分类由 `text_7w.py scan` 覆盖；已确认 `font16.sfo`
> 后，正式的解析/导出/重建统一使用 `font_sfo_7w.py`（早期试探性脚本
> `font_tool_7w.py` 已删除）。

## 一键构建（build_all.py）

`tools/build_all.py` 串联整条汉化构建链：

```text
1. collect   从翻译草稿收集去重中文字符集（work/font/char_set.txt）
2. alloc     只增不改地分配槽位（work/font/char_to_slot.csv，含 CP932 lead/trail）
3. write-font 由 char_to_slot 生成 sub0_map.tsv，再经 font_sub0_7w.py 把字形
             渲染写入目标字库（默认 common.fhm sub0）
4. write     spl / nht / fhm 翻译草稿回写进 unpacked 树
5. write-image 把 work/imageedit 下仍存在的 PNG 回写进 unpacked 树
              （ITE / FHN 内嵌 / GIM；尺寸不符的图**跳过并警告，不中断**）
6. install   把重建字库装进 unpacked 树（替换原文件）
7. repack    重建 CDIMAGE.BIN（work/build/CDIMAGE.BIN）
8. pack      （可选）通过临时 XML 让 mkps2iso 直接读取 work/build 下的
             新 CDIMAGE.BIN/MOVIMAGE.BIN，生成可启动 ISO（--pack-dir / --mkps2iso）
```

图片回写是可选步骤：仅当 `work/imageedit/manifest.csv` 存在（即已将导出
manifest 和待回写 PNG 准备到 imageedit）时执行；无 manifest 或无 PNG 时打印
提示后跳过，不报错。
回写详细规则见下节"图片导出回写规范"。

### 默认流程：common.fhm sub0（对白字库）

以下命令均在**项目根目录**执行，相对路径以项目根为基准。

```powershell
python tools\build_all.py `
  --image mkps2iso-1.1.1-win64\Seven\CDIMAGE.BIN.prev `
  --unpacked unpacked\CDIMAGE_FULL `
  --translation work\translation `
  [--font work\font\chinese.ttf] `
  [--out work\build\CDIMAGE.BIN]
```

`--image` 同时提供 repack 的**骨架镜像**和文本回写前的恢复源。因此当执行
`write` 时，它必须是**未汉化的原版日文 CDIMAGE.BIN**；也可用
`--original-tree` 指定对应的干净解包树。不能把已汉化的 CDIMAGE.BIN 当作恢复源，
否则旧槽位编码的对白会与新分配的字库混用。只有完全跳过文本回写时，才可把其它
完整镜像作为纯 LBA/长度骨架。

默认只把中文字形写入 `chiibaya/common/common.fhm` 的 sub0（24x24），并安装
到 unpacked 树同路径。

### --font-target both：同时写 font16.sfo

若部分 UI/非对白文本渲染自 `arita/font16.sfo`，加 `--font-target both` 会在
sub0 之外**再写一份 font16.sfo**（16x16）并安装到 unpacked 树：

```powershell
python tools\build_all.py `
  --image mkps2iso-1.1.1-win64\Seven\CDIMAGE.BIN.prev `
  --unpacked unpacked\CDIMAGE_FULL `
  --translation work\translation `
  --font-target both
```

CP932 字节由 alloc 从 font16 反推，同一字节在两套字库各自 lookup 下定位
正确索引（如 0x8A9A：sub0→idx907、font16→idx910），故两库同时覆盖时无论
文本走哪条渲染路径都显示中文。

### pack：生成可启动 ISO（mkps2iso）

加 `--pack-dir`（可选 `--mkps2iso`）后，build_all 在 repack 完成后会自动生成
ISO：

```powershell
python tools\build_all.py `
  --image mkps2iso-1.1.1-win64\Seven\CDIMAGE.BIN.prev `
  --unpacked unpacked\CDIMAGE_FULL `
  --translation work\translation `
  --font work\font\chinese.ttf `
  --pack-dir mkps2iso-1.1.1-win64\Seven
```

- `--pack-dir`：mkps2iso 项目目录（含 XML 的 `directory_tree source` 同名目录）。
  对应 XML 自动探测（`find_xml`）。
- `--mkps2iso`：mkps2iso.exe 路径，默认取 `--pack-dir` 同级目录下的
  `mkps2iso.exe`。
- 行为：复制原 XML 到同目录的临时文件，仅给 `CDIMAGE.BIN` 和已有的
  `MOVIMAGE.BIN` `<file>` 节点增加 `source` 属性，使 mkps2iso 直接读取
  `work/build` 中的完整重建文件；随后运行 `mkps2iso -y <临时xml>`，产出
  ISO（`image_name` 定义在 XML，即 `mkps2iso.iso`）。临时 XML 会在结束后删除，
  原 XML 和 mkps2iso 源目录中的大文件不再被覆盖或复制。
- 这不是跳过资源：ISO 中仍按原 XML 的文件顺序、LBA、时间和完整文件内容生成，
  只是省去约 1.2 GB 的中间 staging I/O。
- 已验证：ISO 内 CDIMAGE.BIN 与 `work/build/CDIMAGE.BIN` 哈希一致，大文件
  （SNDIMAGE/MOVIMAGE）未破坏，`dumps2iso` 可完整解析。
- 可在 PCSX2 加载 `mkps2iso-1.1.1-win64\mkps2iso.iso` 运行验证。

### 跳过某步


### FHN 界面文本提取与写回

`takeshi/screen/*.fhn` 中有 42 个界面资源包含固定字段文本；当前工具扫描其中
40 个文件、提取 222 条记录。`mov/opt` 仍由 `ui_write.py` 的旧版固定偏移流程
负责，不能重复加入本工具的候选。其余 `kimura/ef/*.fhn` 是演出/特效数据，
不按句子文本提取。部分界面标签位于 FHN 记录的固定 0x40 字节文本字段中，
不能用全文件的 Shift-JIS 扫描直接替换，否则可能破坏图片/控制数据。先按已确认
的记录结构提取候选：

```powershell
python tools\fhn_text_7w.py extract `
  --unpacked unpacked\CDIMAGE_FULL `
  --output work\translation\fhn
```

候选文件采用 `[text:n] @0xOFFSET len=BYTES | 原文|译文` 格式，字段内的 `$G/$H/$V`
等控制码会显示为 `{G01}`、`{H06}`、`{V10}` 等 ASCII 占位符；字段内部的 NUL
分隔符显示为 `{Z}`，裸字段控制字节显示为 `{C01}` 等，写回时均自动还原。
`build_all.py`
默认在 `ui` 阶段之后执行 FHN 写回；每个文件写回前从
`--original-tree`（或 CDIMAGE manifest）恢复原始字节，只覆盖 0x40 字节文本字段，
记录尾部参数保持不变。启用 `--write-images` 时，build_all 会先写 FHN 文本，
再由图片工具原位更新其中的 ITE，避免图片回写覆盖文本。可用 `--skip fhn`
暂时跳过该阶段。

## 图片导出回写规范（image_7w.py）

`tools/image_7w.py` 统一管理 ITE / FHN 内嵌 ITE / GIM 图片的**批量导出**与
**筛选后回写**，流程与文本/字库一致：

```text
1. scan       扫描 unpacked 树中的静态图片来源，写入 manifest.csv（2844 项：
               2123 个 ITE（含独立 ITE 与各类容器）+ 71 NHT ITE + 650 个 GIM；
               默认跳过 `.fit` / `.aal` 动画帧）
2. export     按 manifest 批量解码成 PNG，镜像到 work/image/
3. (人工)     将要汉化的 PNG 和 manifest 复制到 work/imageedit/，再编辑 PNG
4. write-back 读取 work/imageedit/ 下仍存在的 PNG，重新编码回写进 unpacked 树
              （覆盖源文件）
```

### 命名规范（路径即身份）

```text
导出独立 ITE  work/image/ite/<相对路径>/<name>.png          （如 futamura/title/ttlh_m1.png）
导出 FHN ITE   work/image/ite/<相对路径>/<stem>__ite<NNN>.png （NNN = 内嵌 ITE 序号，同 ite_7w.py）
导出 NHT ITE   work/image/ite/<相对路径>/<stem>__ite<NNN>.png （NNN = NHT 图片序号，从 0 开始）
导出容器 ITE   work/image/ite/<相对路径>/<源文件>__ite<NNN>.png （NNN = 容器内有效 ITE 序号）
导出 GIM       work/image/gim/<相对路径>/<name>.png
导出容器 GIM   work/image/gim/<相对路径>/<源文件>__gim<NNN>.png
回写输入       work/imageedit/（保持上述相对路径）
```

### 常用命令

```powershell
# 1. 全量扫描（首次或 unpacked 变更后）
python tools\image_7w.py scan --unpacked unpacked\CDIMAGE_FULL

# 2. 全量导出 PNG
python tools\image_7w.py export --unpacked unpacked\CDIMAGE_FULL

# 使用原版镜像解包树时，可指定独立的 PNG 输出目录
python tools\image_7w.py export --unpacked temp\image_original_tree `
  --manifest work\image_original\manifest.csv --output work\image_original

# 2b. 只导出某个子目录（分批/测试）
python tools\image_7w.py export --unpacked unpacked\CDIMAGE_FULL `
  --filter "screen/name/name.fhn"

# 如确需导出动画容器中的帧，扫描时显式开启；通常会显著增加耗时和体积
python tools\image_7w.py scan --unpacked unpacked\CDIMAGE_FULL `
  --include-animation

# 3. (人工) 删掉无文字的 PNG、编辑要汉化的 PNG

# 4. 回写：只处理仍存在的 PNG（被删的保持原样）
python tools\image_7w.py write-back --unpacked unpacked\CDIMAGE_FULL
```

### 规则要点

- **删 = 不动**：回写只处理磁盘上仍存在的 PNG，删除的 PNG 对应源资源保持原版。
- **尺寸守护 = 跳过不中断**：PNG 宽高与源不等的图（ITE / FHN 内嵌 / GIM 一律）
  会以 `[skip] size mismatch: ...` 打印说明并**跳过该图不写回**，其余图片正常
  处理，整个流程不中断、`exit=0`。跳过汇总见 `write-back: skipped N image(s)`。
- **FHN 回写**：同源 FHN 的多个 PNG 一次重建整个 FHN；固定槽位的子图以
  `q=4` 重建超长时，会自动按 `q=5..10` 逐级降低质量重试，仍无法放入时
  才**仅跳过该子图**，其余子图照常回写。末尾槽位可以随容器一起增长。
- **GIM 回写**：保留原容器结构（8bpp/4bpp 保留原调色板，未编辑像素精确回映射、
  新增颜色量化到最近色；32bpp 直接写 RGBA 并保留原 alpha）。PNG 宽高必须等于
  源 GIM，否则跳过。identity 回写渲染逐像素一致（全库 298 个实测；调色板有
  重复色时字节可不同但渲染相同）。
- 导出 manifest：`work/image/manifest.csv`；回写 manifest：
  `work/imageedit/manifest.csv`（两者字段相同）。
- 依赖 FFmpeg（`ite_7w.py` 自动查找 `imageio-ffmpeg` 或 `--ffmpeg`）。

## MOVIMAGE 影片字幕

完整的块布局、运行时字段、调试定位、独立解析伪代码与移植建议见
`docs/MOVIMAGE影片字幕格式与解析说明.md`；本节只保留本工程的常用命令和产物流程。

影片下方字幕不是 `mov.fhn` 菜单文本，而是 `MOVIMAGE.BIN` 内的固定长度、单字节
异或保护字幕块。运行时加载器把块内 `0x7F0` 字节用密钥异或后，按回车分隔的
`HHHH:HHHH 文本`记录解析，最后以 `#####` 结束；当前版本也兼容带空格的三位时间码（如 ` 129: 206 文本`）。工具不会修改输入文件：

```powershell
# 已确认的开场旁白块（资源偏移来自原始 MOVIMAGE.BIN）
python tools\movie_subtitle_7w.py extract `
  unpak\MOVIMAGE.BIN `
  --offset 0xCA78010 --key 0x0A `
  temp\movie_subtitle.txt

# 编辑 temp\movie_subtitle.txt 后，生成副本；原 MOVIMAGE.BIN 保持不变
python tools\movie_subtitle_7w.py write `
  unpak\MOVIMAGE.BIN `
  temp\movie_subtitle.txt `
  work\build\MOVIMAGE.BIN `
  --offset 0xCA78010 --key 0x0A `
  --map work\font\sub0_map.tsv
```

全量扫描当前版本的所有字幕块（输出 manifest 和逐块文本）：

```powershell
python tools\movie_subtitle_7w.py scan `
  unpak\MOVIMAGE.BIN `
  work\text\movie_subtitles
```

全部字幕翻译完成后批量回写：

```powershell
python tools\movie_subtitle_7w.py write-all `
  unpak\MOVIMAGE.BIN `
  work\text\movie_subtitles `
  work\build\MOVIMAGE.BIN `
  --map work\font\sub0_map.tsv
```

文本行格式为 `时间码|译文`，时间码不可修改；工具保留 `#####`、填充区和未改动
行的原始 CP932 字节，原样提取后回写可逐块字节一致。不同影片块需在 PCSX2
的字幕解析断点 `0x0012B620` 处读取 `a2`（原始缓冲区）和 `t0`（异或密钥），
再把对应资源偏移传给工具。生成的 `MOVIMAGE.BIN` 需要放入 mkps2iso 打包目录
并重新制作 ISO。现在如果 `work/videoedit/19_op.mp4` 存在，`build_all.py` 会在字幕回写
之后自动执行视频反写：按原始 60 个固定块的帧数分段编码为 MPEG-2（q8、18 帧 GOP、
2 个 B 帧），每块补 `sequence_end_code`，只替换视频槽位并保留块内原始 PCM 音频，
再写入 `work/build/MOVIMAGE.BIN`。编码结果如果越过音频起点会直接失败，不会生成损坏的文件。
视频反写阶段可用 `--skip movie-video` 跳过；中间分段和报告放在
`temp/movie_video_build/` 与 `work/report/movie_video_reinject.json`，不会覆盖
`unpak/MOVIMAGE.BIN` 或 MP4。

## 设计原则

- 输入文件只读；输出写往 `work` 子目录：文本→`work/text/raw`、图片导出→
  `work/image`、图片回写输入→`work/imageedit`、翻译→`work/translation`
  （成稿在 `work/text/translated`）、
  报告/manifest→`work/report`、字库→`work/font`。临时/中间产物放 `temp/`，
  不要写进 `work`。
- 先按 magic 分类，再进行文本提取。
- 保留原始偏移和旧长度用于身份校验；SPL/NHT/FHM 写回均通过结构化重建支持
  可变长文本。不可编码文本保留原文并报告。
- 不把 Venus & Braves 的 SFO 结构假定为 7W 的字库结构。
